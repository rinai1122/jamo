# Phase 3: Full Evaluation + Beam Solver

Benchmark: `benchmark_set.json`, seed 1234 — **100** corpus fragments,
variable length 17-167 jamo (avg 61), random bijective keys. Generated by
`benchmark.py`; every solver below saw identical data.

## Results (100 cases)

| Solver | Avg acc | Solved (>=90%) | s/case | by length: <70 / 70-120 / >=120 |
|---|---|---|---|---|
| NN v4 (`nn_v4.py`) | 22.09% | 0 | 1.5 | 25% / 22% / 0%* |
| NN v5 (`nn_v5.py`) | 22.67% | 0 | 0.7 | 25% / 24% / 0%* |
| HC baseline (`lean_solver.py`) | 43.51% | 2 | 39 | 40% / 56% / 37% |
| HC improved (`improved_solver.py`) | 77.01% | 56 | 172† | 70% / 92% / 93% |
| HC v2 (`improved_solver_v2.py`) | 76.16% | 54 | 202† | 68% / 93% / 96% |
| **Beam (`beam_solver.py`)** | **96.25%** | **94** | **3.5** | **95% / 99.8% / 100%** |

\* v4/v5 were built with max_len=100 and error out on the 8 longer cases.
† HC v1/v2 ran 3-4 solvers concurrently on 8 cores; solo wall time is
roughly 2-3x lower. Budget was the standard 30 restarts x 5000 iters.

HC v2's elitism + reheating did **not** beat HC v1 — the extra machinery
is not where the headroom was.

## The beam solver (new)

Key idea: a bijective substitution preserves each word's repetition
pattern, and spaces survive encryption — so each cipher word indexes a
small candidate set in a pattern dictionary built from **all** 357k
distinct corpus words (the old DictionaryAnchor used only the top 10k).
89.5% of benchmark words occur verbatim in the corpus; a 10-jamo word has
a median of 41 pattern-compatible candidates, a 12-jamo word just 3.

Pipeline per ciphertext:
1. **Beam search over words, most-constrained first** (width 500). Each
   state is a partial key; extensions are pattern-candidates consistent
   with the state (position-indexed set intersection), plus a "skip"
   branch (logprob -10) for out-of-dictionary words. Matched words score
   log10(corpus count / total).
2. **KN rerank**: top-30 beam states are completed (frequency-rank fill
   of unmapped symbols) and reranked by the order-6 KN fitness +
   structure DFA + dictionary bonus (reused from HC v2).
3. **Edge-truncation pass**: if dictionary coverage < 95%, rerun the beam
   letting the first word match *suffixes* and the last word *prefixes*
   of corpus words (fragments are cut mid-word; this fixed two 17-77%
   cases to 100%).
4. **Fallbacks**: coverage < 30% (e.g. spaceless text, no word anchors)
   -> full HC v2 search, keep the better by fitness. Coverage < 85% or
   structure violations -> short anneal (8x1500) seeded with beam elites.
5. **Greedy polish** (exhaustive swaps + unused-target reassignments).

## What still fails (6 cases < 90%)

All short (17-45 jamo): texts dominated by rare loanwords/emoticons
(ㅠㅠ, 갱스터-무비), and short fragments with multiple dictionary-consistent
readings (ㅎㅎㅎ 농약을 먹이자 vs ㅋㅋㅋ 공연을 뿐이다) — at this length the
cipher is information-theoretically underdetermined (unicity distance),
not a search failure. The one spaceless case lands 40-75% depending on
anneal luck.

## NN v6 / hybrid: dropped

`train_v6.py` (dual-rank 6-layer transformer) ran at ~14 s/step on this
CPU — 6000 steps ≈ 23 h, infeasible. The hybrid plan (NN key seeds HC)
is superseded anyway: the dictionary beam provides far better seeds than
a ~25%-accurate NN ever would.

## Reproduce

python benchmark.py            # regenerate the fixed 100-case set
