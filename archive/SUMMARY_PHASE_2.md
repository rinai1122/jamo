# Phase 2: Weakness Analysis & Improvements

All numbers are average per-character accuracy on a fixed 20-case benchmark
(`benchmark_set.json`, seed 1234: 50-jamo corpus fragments, random keys),
generated by `benchmark.py` and shared by every evaluation.

## Hill-climbing approach

Identical search budget for both (30 restarts x 5000 iterations).

| Solver | Avg accuracy | Solved (>=90%) |
|---|---|---|
| Baseline (`lean_solver.py`) | 36.40% | 1/20 |
| Improved (`improved_solver.py`) | **68.00%** | **6/20** |

Weaknesses found in the baseline and the fixes:

1. **Unreachable keys (the big one).** Initialization sampled ~18 target
   jamos out of ~50, and the only move was swapping two *in-use* targets.
   Any correct jamo missing from the initial sample could never be reached
   within a restart. Fix: 50% of moves re-assign a symbol to an **unused**
   target.
2. **Uncached recursive KN scoring** forced the context down to order 4
   (model is 7-gram). Fix: memoized probabilities, order 6.
3. **+1000 dictionary cliff** let one false pattern match dominate the LM.
   Fix: bonus scales with word length (4/jamo); candidate words per cipher
   word are precomputed once (bijections preserve repetition patterns).
4. **No structural prior.** Decomposed jamo words are strictly `(C V C?)+`.
   Fix: DFA penalty per violation — prunes most of the keyspace.
5. **Random restarts.** Fix: cipher-frequency -> corpus-frequency rank
   seeding (perturbed per restart) + greedy polish pass at the end.

Cost: ~38s/case vs ~19s/case baseline (order-6 scoring + polish pass).

## Neural approach

Same architecture size (d_model 256, 4 heads, 4 layers), same data,
batch 64, seq 50, CPU. Eval = `eval_nn.py`.

| Model | 1200 steps | 2400 steps |
|---|---|---|
| V3 baseline (`nn_model_v3.py`, retrained fairly) | 20.62% | 6.58% (collapsed) |
| V4 (`nn_v4.py`, greedy decode) | **23.95%** | **25.33%** |

Weaknesses found and the fixes:

1. **Meaningless symbol embeddings.** The key is random per sample, so raw
   cipher-symbol IDs carry no transferable signal; V3 had to learn
   permutation invariance by brute force — and with more training it
   overfit to noise (the 2400-step collapse). Fix: canonicalize input by
   frequency rank + first occurrence (`canonicalize`), so id 0 means "most
   frequent symbol", which has a stable plaintext prior.
2. **Decoding ignores cipher constraints.** Per-position argmax can emit
   different jamos for the same cipher symbol. Fix implemented
   (`decode_constrained`: per-symbol logit aggregation + Hungarian
   assignment), but at current model strength it scores slightly below
   greedy (21-22%) — enforcing injectivity hurts when the model leans on
   frequent-jamo priors. Expected to pay off with a stronger model.

Negative results (kept for the record): pre-LN + warmup/cosine @3e-4 +
benchmark-matched clean data (`train_v4b.py`) reached only 21-23% at the
same budget, with or without the final-LayerNorm fix. The input
representation, not the optimization recipe, is what matters here.

## Bottom line

- Hill climbing: 36.4% -> **68.0%** (+31.6 pts), solved cases 1 -> 6, at
  equal search budget.
- NN: 20.6% -> **25.3%** (+4.7 pts) at equal-or-same arch budget, and the
  improved model scales with training while the baseline degrades.
- The statistical approach remains far stronger for this task on CPU
  budgets; the natural next step is hybrid decoding (NN posterior as the
  hill climber's restart seed).

## Reproduce

```
python benchmark.py                 # fixed test set
python eval_hc.py baseline|improved # hill-climbing numbers
python train_compare.py v3|v4 1200  # fair NN training
python eval_nn.py v3|v4|v4_greedy   # NN numbers
```
